결론

제품설계문서의 방향은 “자동주문보다 시장 국면 + 후보 스크리너 + 점수화 + 리스크 계산 + 백테스트 + 자동 리포트”를 먼저 완성하는 구조입니다. 현재 jhonkim91/Stock-Analist-auto-trading 레포는 이 1차 MVP 축을 꽤 많이 구현했습니다. 다만 실데이터 신뢰성, 백테스트 엄밀성, 전략 다양성, paper/live 실행 계층은 아직 미완성입니다. 보고서 기준으로 보면:

영역	현재 상태	평가
FastAPI/Next.js 앱 골격	구현됨	양호
샘플 데이터 + CSV 검증/확정 import	구현됨	양호
시장 국면/기술지표/스크리너/점수화	구현됨	MVP 수준
일간 리포트	구현됨	MVP 수준
백테스트	구현됨	단순 검증용
KIS/브로커 연동	안전 스캐폴드만 구현	의도적으로 주문 차단
실제 자동매매	미구현	다음 단계
실전급 데이터/백테스트 품질	미흡	우선 보강 필요

현재 README도 checkpoint를 MVP v0.6 Phase 3D broker safety scaffold로 두고, 실제 주문, paper/live broker, cancel, fill, websocket, KIS 실제 API 호출, 자동매매 스케줄러, AI 예측 모델은 구현하지 않는다고 명시합니다.
보고서 기준선은 업로드한 deep-research-report.md를 기준으로 봤습니다.

1. 현재 잘 구현된 부분
1) 백엔드/프론트엔드 기본 구조

현재 백엔드는 FastAPI 앱으로 구성되어 있고, data, indicators, market, instruments, screener, reports, backtest, portfolio, broker, kis, settings 라우터가 등록되어 있습니다. 즉, 보고서가 제안한 데이터 → 지표 → 전략/스크리너 → 백테스트 → 리포트 → 실행 어댑터 흐름의 기본 뼈대는 잡혀 있습니다.

판단:

2. 부분 구현 또는 보강이 필요한 부분
1) VCP 구현이 아직 단순함

현재 VCP는 ATR% 축소, STD20 < STD60, volume dry-up, pivot breakout 정도로 판정합니다.
보고서 기준 VCP는 다음까지 필요합니다.

contraction count
pullback 폭 감소 sequence
최종 pivot
최종 수축 저점
breakout volume
실패 시 pivot/last contraction low 이탈

현재는 **“VCP 느낌의 돌파 필터”**에 가깝고, Mark Minervini식 VCP 판정기로는 아직 부족합니다.

2) CAN SLIM도 라이트 버전

현재 CAN SLIM은 EPS growth, sales growth, RS, breakout, bull market 정도입니다.
추가로 필요한 요소는 다음입니다.

CAN SLIM 요소	현재 상태
C: 최근 분기 EPS 성장	있음
A: 연간 EPS 성장	없음
N: 신제품/신고가/신규성	breakout 정도만 있음
S: 수급/유통주식수	없음
L: 리더십	RS로 부분 구현
I: 기관 수급	없음
M: 시장 방향	있음

즉, 현재는 CAN SLIM full 구현이 아니라 CAN SLIM Lite입니다.

3) fundamentals는 point-in-time 형태만 있고, 실제 이벤트/공시 시간 처리가 약함

fundamentals_asof()는 effective_date <= trade_date인 최신 fundamentals를 조회합니다. 이건 룩어헤드 방지의 기본 골격으로 좋습니다.
하지만 보고서 기준으로는 다음이 더 필요합니다.

earnings announcement timestamp
장전/장후 발표 구분
consensus estimate
EPS surprise
revision score
PEAD용 이벤트 window
재무 데이터 원천/공시 시점 audit

현재 fundamentals_pti는 구조상 좋은 출발점이지만, 실전형 실적 모멘텀에는 아직 부족합니다.

4) portfolio risk는 mock/synthetic

PortfolioService는 포지션과 최신 통과 후보를 읽어 risk summary를 만들지만, warning에 “mock/synthetic 상태”, “실제 positions 또는 broker 체결은 Phase 2 범위가 아님”을 명시합니다.

즉, 현재 포트폴리오 리스크는:

실제 계좌 잔고 기반 아님
실제 체결 기반 아님
open positions sync 없음
일간 최대손실 enforcement 없음
섹터/전략/상관 노출 제한 없음

보고서의 리스크 관리 모듈로 가려면 다음이 필요합니다.

portfolio_state
broker_positions_sync
max_daily_loss_guard
max_gross_exposure
sector_cap
symbol_cap
strategy_cap
event_risk_flag
gap_risk_estimator

2) 백테스트 엔진이 아직 연구용 단순 모델

현재 백테스트는 다음 장점이 있습니다.
